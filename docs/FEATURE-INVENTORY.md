## Interfaces

All three interfaces call the same backend (`Get-WtTweakState`, `Invoke-WtTweak`,
`Undo-WtTweak`, `Get-WtHistory`, `Get-WtPreset`/`Import-WtPreset`/`Export-WtPreset`), so dry run,
state capture, verification, logging and rollback behave identically in each of them.

| Interface | Entry point | Purpose | Opens a window |
|---|---|---|---|
| Terminal interface (primary) | `pwsh -File WindowsTweaker.ps1` | Keyboard-driven panes, search, pending changes, dry-run preview, execution history, restore, presets, and an optional icon vocabulary (`Auto`/`Unicode`/`NerdFont`/`ASCII`/`None`, with an in-terminal preview and no font installation). Never opens a graphical surface. Shortcuts: [KEYBOARD.md](KEYBOARD.md) | no |
| Non-interactive CLI | `-List`, `-Status`, `-Id`, `-Preset`, `-PresetList`, `-PresetExport`, `-IncludeRestorePoint`, `-History`, `-Rollback`, `-HistoryId`, `-Report` | Scriptable use of the same backend; meaningful exit codes (0 success/unchanged/dry run, 1 failed/unsupported, 2 nothing to do) | no |
| Optional graphical interface | `-Gui` | WPF front end for Windows hosts that prefer a window; identical guarantees, same backend | yes (Windows only) |

Terminal workflow coverage (the workflows the legacy tool did in windows):

| Legacy graphical workflow | Terminal replacement |
|---|---|
| Store package picker | `Apps.UninstallUwpPackage` picker: searchable list, explicit multi-selection, package details, `U` switches the user scope; protected and non-removable packages cannot be ticked |
| Windows features / capabilities | `Apps.WindowsFeature` / `Apps.WindowsCapability` pickers listing every entry with its current state (`Get-WtWindowsFeature`, `Get-WtWindowsCapability`) |
| Adapter / DNS configuration | `Network.DnsOverHttps` workflow: adapter list with the current DNS servers, virtual/VPN adapters confirmed separately, validated IPv4/IPv6 input, optional DoH template |
| File dialogs (import/export) | Text dialogs with path validation (absolute path, extension, existing directory, no silent overwrite) |
| Message boxes | In-screen message, confirmation and progress panels |
| External Windows settings pages | None of the exposed tweaks needs one, and the interface layer is test-guarded against launching anything (no `Start-Process`, no shell APIs, no graphical surface in `Private/Tui`). Anything added later that does need a settings page has to be labelled explicitly rather than opening it silently |
| Restore points | Supplementary and never implicit: `Invoke-WtTweak -IncludeRestorePoint` (also `-IncludeRestorePoint` on the CLI) asks for one, and the terminal interface never creates one on its own |

## Presets

A preset is a reviewed list of "tweak -> requested state" entries in JSON. Loading one fills the
pending changes; it applies nothing. Shipped presets must not contain protection-reducing or
irreversible entries and are checked by `tests/Tui.Tests.ps1`.

| Preset | Source | Entries | Description |
|---|---|---|---|
| `explorer-usability` | built-in | 10 | Convenience choices for File Explorer and the taskbar (visible extensions, detailed transfer dialog, left-aligned search icon). Subjective defaults - review before applying. |
| `privacy-hardening` | built-in | 18 | Reduces data collection and advertising surfaces. Review every entry before applying; nothing is applied automatically. |

### `Apps.AutoPlay`

* **Name**: Tự động phát cho ổ đĩa và thiết bị
* **Description**: Bật hoặc tắt Tự động phát cho ổ đĩa và thiết bị tháo rời, đồng thời xóa chính sách autorun cũ vốn sẽ ghi đè lựa chọn này.

* **Scope / privileges**: UserAndMachine / Admin
* **Restart required**: Explorer
* **Rollback**: đầy đủ (đúng trạng thái trước đó)
* **Requirements**: Cmdlet:Get-ItemProperty
* **Risk**: Low
* **Operations per state**:
  * `Enabled`: RegistryRemove + RegistryRemove + RegistrySet
  * `Disabled`: RegistryRemove + RegistryRemove + RegistrySet

* **Requirements**: Cmdlet:Get-ItemProperty
